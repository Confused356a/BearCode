# Bear Code 长程任务测评说明

## 数据集概览

Bear Code 当前使用已处理好的 GAIA 与 HLE 子集，共 665 道任务。原始 benchmark 的规模和当前项目实际评测规模分开统计：

| 数据集 | 原始 benchmark 规模 | 当前项目评测规模 | 当前题型分布 |
| --- | ---: | ---: | --- |
| GAIA | 466 题，其中 300 题为留出的测试集 | 165 题 | Text 103、MM 24、File 38 |
| HLE | 2,500 题高难度跨学科题目 | 500 题 | Text 387、MM 113 |
| 合计 | - | 665 题 | 覆盖文本、多模态与文件任务 |

### GAIA 简介

GAIA 面向通用 AI Assistant，题目通常要求 Agent 完成多步信息收集、网页浏览、文件处理、代码执行、视觉理解和结果验证。它不是单纯的知识问答：Agent 需要持续维护任务目标、已获得证据、已完成步骤和待办事项，才能在多轮工具调用后给出正确结论。

因此，GAIA 是 Bear Code 验证自主会话记忆折叠的主要数据集，尤其适合检验：

- 折叠后是否保留文件路径、网页证据、计算结果和用户约束；
- Agent 是否能从历史工具失败中恢复并调整策略；
- 在上下文受限时，是否仍能完成多工具协作任务。

### HLE 简介

HLE 是高难度跨学科推理 benchmark，覆盖数学、物理、化学、生物医学、计算机、工程、人文社科等领域。当前项目使用的 500 题子集包含 372 道精确匹配题和 128 道多选题。

HLE 更强调最终答案正确性、复杂推理和多模态理解。它用于验证 Bear Code 在长上下文或完成会话折叠后，能否保留关键条件、推理约束和已验证事实，避免因上下文压缩导致最终答案退化。

## 1. 测评目标

Bear Code 当前使用 GAIA 与 Humanity's Last Exam（HLE）的 665 道任务，评估 Agent 在长程、多工具任务中的实际完成能力，以及自主会话记忆折叠对任务连续性的影响。

该测评参考 DeepAgent 的下游任务评测方式，但结合 Bear Code 的能力边界进行调整：

- Agent 在同一条会话中完成多步检索、文件处理、代码执行、图片理解或项目操作；
- Agent 可以在上下文变长、工具结果噪声较多、重复失败或需要调整策略时调用 `compact_context`；
- Runtime 将历史会话折叠为 `episode_memory`、`working_memory`、`tool_memory`，并从折叠后的结构化状态继续执行；
- 测评只看最终答案是否正确，以及折叠后能否保持任务推进。

## 2. 数据集与任务范围

### 2.1 GAIA 子集

GAIA 当前评测 165 题，覆盖三类任务：

| 类型 | 标记 | 题数 | 典型能力 |
| --- | --- | ---: | --- |
| 文本任务 | `text` | 103 | 多轮检索、网页阅读、信息交叉验证、计算与归纳 |
| 多模态任务 | `mm` | 24 | 图片理解、视觉问答、文本与图像证据结合 |
| 文件任务 | `file` | 38 | 读取 PDF、表格、文档、音频或压缩文件，并完成分析和计算 |

GAIA 适合验证 Bear Code 是否能在多轮工具调用中维护任务目标、中间证据、已完成步骤和待办事项，因此是自主会话记忆折叠的主要长程任务评测集。

### 2.2 HLE 子集

HLE 当前评测 500 题，包含文本与多模态样本：

| 类型 | 标记 | 题数 | 典型能力 |
| --- | --- | ---: | --- |
| 文本任务 | `text` | 387 | 数学、科学、人文和专业领域推理 |
| 多模态任务 | `mm` | 113 | 结合图片、图表或视觉信息的高难度推理 |

HLE 更强调最终答案的精确性和深度推理质量。相比 GAIA，它不一定有很长的工具链，但可以检验记忆折叠后是否保留关键推理约束、已验证事实和未解决问题。

## 3. 单题执行流程

每条样本只运行一条 Agent 轨迹：

```text
加载任务与工具
  -> Bear Code 开始会话
  -> 推理 / 工具调用 / 读取结果
  -> 必要时调用 compact_context 或由 Runtime 阈值触发折叠
  -> 注入结构化会话记忆并继续任务
  -> 输出最终答案
  -> 计算 Pass@1
```

Bear Code 的折叠状态以 `episode_memory`、`working_memory`、`tool_memory` 三层 JSON 保存到 `.bear/sessions/`。在当前测评里，它们只作为帮助 Agent 继续完成任务的结构化状态，不单独作为评测指标。

## 4. Pass@1

`Pass@1` 表示每道题只执行一次，最终是否完成任务。

设测试集有 \(N\) 道题，第 \(i\) 道题的最终判定为 \(c_i\)：

\[
c_i =
\begin{cases}
1, & \text{最终答案正确}\\
0, & \text{否则}
\end{cases}
\]

\[
\mathrm{Pass@1} = \frac{1}{N}\sum_{i=1}^{N}c_i
\]

含义：在不重试、不挑选多次采样中最佳答案的前提下，Bear Code 一次完成任务的成功率。这是本测评唯一主指标。

## 5. 当前项目测评结果

当前项目在 165 道 GAIA 任务和 500 道 HLE 任务上执行单条 Agent 轨迹，并按最终答案正确性统计 `Pass@1`。结果如下：

| 数据集 | 类型 | 通过题数 / 总题数 | Pass@1 |
| --- | --- | ---: | ---: |
| GAIA | Text | 60 / 103 | 58.3 |
| GAIA | MM | 8 / 24 | 33.3 |
| GAIA | File | 20 / 38 | 52.6 |
| GAIA | All | 88 / 165 | 53.3 |
| HLE | Text | 84 / 387 | 21.7 |
| HLE | MM | 17 / 113 | 15.0 |
| HLE | All | 101 / 500 | 20.2 |

GAIA 是当前验证长程多工具能力的主评测集。Text、MM、File 三类题的通过题数合计为 88，因此：

\[
\mathrm{GAIA\text{-}All}=\frac{88}{165}=53.3\%
\]

HLE 的 Text、MM 两类题通过题数合计为 101，因此：

\[
\mathrm{HLE\text{-}All}=\frac{101}{500}=20.2\%
\]

## 6. 会话记忆折叠对照

为验证自主会话记忆折叠对长程任务的实际价值，在相同任务集合和模型配置下，对比开启和关闭结构化会话记忆折叠的结果：

| 配置 | GAIA All Pass@1 | 结论 |
| --- | ---: | --- |
| 开启结构化会话记忆折叠 | 53.3 | 保留任务进度、当前工作状态和工具经验后继续执行 |
| 关闭会话记忆折叠 | 44.7 | 长历史和失败路径无法有效重组，长程任务成功率下降 |

关闭折叠后，GAIA `Pass@1` 从 53.3 降至 44.7，下降 8.6 个百分点。这表明会话折叠的收益不只是减少上下文长度，更体现在折叠后仍能保留关键状态、避免重复失败，并继续推进长程任务。

HLE 当前用于验证最终推理质量和折叠后的答案保持能力；当前结果表中不单独报告 HLE 的关闭折叠对照分数。

## 7. 结论

GAIA 和 HLE 的部分样本为 Bear Code 提供了两种互补的测评视角：

- GAIA 验证多工具、文件、多模态和长程状态维护能力，是验证自主会话记忆折叠的主场景；
- HLE 验证高难度最终推理质量，以及折叠后关键约束和证据是否被正确保留；
- `Pass@1` 是唯一主指标；
- 仅当结构化会话记忆在相同配置下保持或提高 `Pass@1`，才能说明它真正提升了长程任务能力。
