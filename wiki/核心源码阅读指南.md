# Bear Code 核心源码阅读指南

本文档面向想快速读懂 Bear Code 代码的人。它不是按文件名堆清单，而是按“先看主链路，再看能力模块，最后看沉淀与评测”的顺序来组织。

如果你只想知道这个项目到底怎么跑，先看 `README.md` 和 `wiki/架构设计.md`。如果你想真正读源码，建议按本文档的顺序走一遍。

## 1. 先建立整体心智

Bear Code 的核心不是单个工具，而是一套 Coding Agent Runtime：

```text
用户输入
  -> main.py 解析参数和模式
  -> Agent.chat() 进入一轮对话
  -> 构建 prompt / 检索 Skills / 预取 Memory / 初始化 MCP
  -> 模型返回 tool call
  -> Runtime 做权限判断
  -> 执行工具、Skill、MCP 或子 Agent
  -> 工具结果回写模型
  -> 必要时 compact_context
  -> 保存 session
  -> 后台触发 Skills 自进化和评测
```

所以这份源码阅读指南的目标只有四个：

1. 看懂一次请求如何进入 Agent Loop。
2. 看懂工具、权限和上下文是怎么被 Runtime 管住的。
3. 看懂 Skills、Memory、MCP、子 Agent 是怎么接入的。
4. 看懂自进化和评测是怎么形成闭环的。

## 2. 推荐阅读顺序

建议按下面顺序读：

1. `agents/main.py`
2. `agents/agent.py`
3. `agents/tools.py`
4. `agents/prompt.py`
5. `agents/skills.py`
6. `agents/online_skill_evolution.py`
7. `agents/skill_evolution.py`
8. `agents/online_skill_eval.py`
9. `agents/session_memory.py`
10. `agents/memory.py`
11. `agents/mcp_client.py`
12. `agents/subagent.py`
13. `agents/session.py`、`agents/ui.py`、`agents/frontmatter.py`

阅读顺序的原则是：

- 先主链路，再辅助模块；
- 先运行时，再持久化；
- 先理解“怎么跑”，再理解“怎么沉淀”。

## 3. 第一站：`agents/main.py`

`main.py` 是入口层，负责把命令行参数和环境变量变成 Agent 配置。

重点看这些事：

- CLI 参数怎么解析；
- `--plan`、`--resume`、`--accept-edits`、`--yolo`、`--dont-ask` 怎么映射为权限模式；
- `API` / `APIKEY`、`OPENAI_*`、`ANTHROPIC_*` 怎么决定模型接口；
- REPL 和 one-shot 模式怎么分流；
- `--resume` 如何恢复最近一次 session。

你只需要记住一点：

> `main.py` 不负责做 Agent，它负责把“怎么运行 Agent”这件事配置好。

### 3.1 建议先看

- `parse_args()`
- `_resolve_permission_mode()`
- `_resolve_api_config()`
- `run_repl()`
- `run_one_shot()`
- `main()`

### 3.2 读完以后应该知道

- 模型从哪来；
- 权限模式怎么定；
- 什么时候进入 REPL，什么时候一次性执行；
- `--resume` 恢复的是哪部分会话状态。

## 4. 第二站：`agents/agent.py`

`agent.py` 是整个项目最核心的运行时。

### 4.1 先看 `Agent.__init__()`

先搞懂 Agent 持有哪些状态：

- `permission_mode`
- `model`
- `use_openai`
- `tools`
- `_mcp_manager`
- `_anthropic_messages` / `_openai_messages`
- `_read_file_state`
- `_already_surfaced_memories`
- `_pending_skill_extraction_window`
- `_background_skill_tasks`
- `_folded_session_memories`
- `_base_system_prompt` / `_system_prompt`

这些字段基本就是整个 Runtime 的状态图。

### 4.2 再看 `Agent.chat()`

这是每轮对话的总入口，建议按这个顺序读：

```text
chat(user_message)
  -> 初始化 MCP
  -> 合并上一轮 pending window
  -> 注入 Skills 上下文
  -> 选择 OpenAI / Anthropic 主循环
  -> 等待模型输出和工具循环
  -> 调度 usage tracking
  -> 调度 online skill evolution
  -> 记录新的 pending window
  -> 自动保存 session
```

你读 `chat()` 的时候，重点不是细节，而是理解：

- 为什么一轮对话不是一次模型调用；
- 为什么会有后台任务；
- 为什么会有 pending window；
- 为什么 session 要自动保存。

### 4.3 再看工具总入口 `_execute_tool_call()`

这是模型动作真正进入系统的地方。建议把它当作运行时路由表来看：

- `compact_context` -> 会话折叠
- `enter_plan_mode` / `exit_plan_mode` -> 计划模式切换
- `agent` -> 子 Agent
- `skill` -> Skill 调用
- `mcp__...` -> MCP 工具
- 其他工具 -> `agents/tools.py`

### 4.4 再看这几个辅助函数

- `_compact_conversation()`
- `_compact_openai()` / `_compact_anthropic()`
- `_generate_folded_session_memory()`
- `_record_folded_session_memory()`
- `_run_compression_pipeline()`
- `_check_and_compact()`
- `_auto_save()`
- `restore_session()`

看完这一组，你就能知道：

- 会话记忆怎么折叠；
- 折叠产物保存到哪里；
- 什么时候自动压缩；
- 为什么 `--resume` 只是恢复会话，而不是重建完整工作状态。

## 5. 第三站：`agents/tools.py`

`tools.py` 解决的是“模型能做什么，什么能做，什么时候能做”的问题。

### 5.1 先看工具定义

重点看 `tool_definitions`：

- `read_file`
- `write_file`
- `edit_file`
- `list_files`
- `grep_search`
- `run_shell`
- `skill`
- `compact_context`
- `skill_create`
- `skill_evolve`
- `enter_plan_mode`
- `exit_plan_mode`
- `agent`
- `tool_search`

### 5.2 再看权限

重点看：

- `check_permission()`
- `_check_permission_rules()`
- `_confirm_*` 相关逻辑

你要重点理解几类硬边界：

- 只读工具直接允许；
- Plan Mode 阻断编辑和 Shell；
- 危险 Shell 需要确认；
- 新文件、Skill 创建和 Skill 演化需要确认；
- `dontAsk` 会拒绝需要确认的动作。

### 5.3 再看编辑前读取保护

Bear Code 不是只靠 prompt 说“先读后改”，而是做了硬检查：

- 先 `read_file`
- 记录路径和 mtime
- 编辑前检查是否读过
- 如果文件被外部改过，要求重新读取

这部分是项目里很值得讲的工程保护线。

## 6. 第四站：`agents/prompt.py`

`prompt.py` 的作用是把运行时上下文拼进 system prompt。

建议重点看它如何注入：

- 项目规则
- Memory 说明
- Skills 列表
- 子 Agent 类型
- deferred tools
- 当前工作目录和 git 状态

你会发现 Bear Code 不是把 prompt 写死的，而是把 prompt 当作运行时配置的一部分。这个设计和 Harness 思路是一致的。

## 7. 第五站：`agents/skills.py`

`skills.py` 负责 Skills 的发现、检索、执行和缓存。

### 7.1 先看 `discover_skills()`

它会扫描两类目录：

- 用户级 `~/.bear/skills/`
- 项目级 `<cwd>/.bear/skills/`

重点理解：

- 为什么用户级优先级更高；
- 为什么项目级不会覆盖同名用户级 Skill；
- `SKILL.md` 是怎么解析成 `SkillDefinition` 的。

### 7.2 再看 `retrieve_relevant_skills()`

这部分是轻量检索，不是重型向量召回。你要理解：

- 为什么 `name`、`description`、`when_to_use` 权重更高；
- 为什么还要看正文；
- 为什么返回的是 top hits；
- 为什么会把结果注入 `<retrieved_skills>`。

### 7.3 再看 `execute_skill()`

它决定 Skill 是：

- 直接注入当前上下文，还是
- 以 fork 模式拉起子 Agent

读这一段时要明白：Skill 不是 prompt 文本本身，而是可复用任务方法。

## 8. 第六站：`agents/online_skill_evolution.py`

这部分是 Skills 自进化入口。

建议按这个顺序看：

1. `extract_online_skill_candidate()`
2. `maintain_online_skill_candidate()`
3. `online_ingest()`

你要抓住的核心不是 JSON schema，而是流程逻辑：

- 用户后续反馈是证据；
- Extractor 最多抽一个候选；
- Maintainer 决定 add / merge / discard；
- 不能把一次性内容写成长期能力；
- 结果会写 provenance。

这部分是 Bear Code 把“反馈”变成“能力”的关键。

## 9. 第七站：`agents/skill_evolution.py`

这部分负责 Skill 的落盘、版本和审计。

重点看：

- `create_skill_file()`
- `evolve_skill_file()`
- `record_online_skill_provenance()`
- `record_skill_invocation()`
- `record_skill_usage_judgments()`

你读完以后应该能回答：

- Skill 文件写到哪里；
- 版本怎么 bump；
- 旧版本怎么留档；
- provenance 和 usage stats 怎么记录；
- 为什么自进化不是直接覆盖 active Skill。

## 10. 第八站：`agents/online_skill_eval.py`

这是 Skills 质量评测的核心。

建议理解它的四层结构：

```text
provenance
  -> replay pool
  -> rules / LLM judge
  -> candidate variants / champion
```

重点看这些函数：

- `evaluate_online_skill_evolution()`
- `evaluate_online_skill_evolution_async()`
- `_build_replay_pool()`
- `_compile_eval_rules()`
- `_evaluate_rule_async()`
- `_build_candidate_eval_bundle_async()`
- `_set_champion()`

你需要真正理解的是：

- 为什么评测不是只看一个文件；
- 为什么要先回放历史样本；
- 为什么要区分 current active 和 candidate；
- 为什么 champion 只是本地健康版本记录。

## 11. 第九站：`agents/session_memory.py`

这是自主会话记忆折叠的 schema 文件。

重点看三件事：

- `FOLD_SESSION_MEMORY_SYSTEM`
- `parse_folded_memory()`
- `fallback_folded_memory()`

这里定义了三层结构：

- `episode_memory`
- `working_memory`
- `tool_memory`

你要理解的是：它不是普通摘要，而是面向后续继续执行的结构化状态。

## 12. 第十站：`agents/memory.py`

`memory.py` 负责长期记忆的文件化保存与召回。

建议按这个顺序看：

- `get_memory_dir()`
- `save_memory()`
- `list_memories()`
- `scan_memory_headers()`
- `select_relevant_memories()`
- `start_memory_prefetch()`

重点理解：

- Memory 和 session memory 不是一回事；
- Memory 是跨会话的长期记忆；
- 召回前先扫 header，再决定是否读正文；
- 长记忆注入有预算控制。

## 13. 第十一站：`agents/mcp_client.py`

这部分负责 MCP 接入。

先看两个类：

- `McpConnection`
- `McpManager`

你要知道它做了什么：

- 读取配置；
- 启动 MCP server；
- 做 initialize；
- 拉 tools/list；
- 将 MCP 工具包装成 Agent tool；
- 用 `mcp__server__tool` 命名路由调用。

这部分的关键不是 SDK，而是协议层被自己实现了。

## 14. 第十二站：`agents/subagent.py`

子 Agent 是把上下文隔离开的一层。

重点理解：

- `explore` 是只读搜索；
- `plan` 是只读规划；
- `general` 是独立执行局部任务；
- 自定义 Agent 可以从 `.bear/agents/*.md` 里加载；
- `allowed-tools` 决定子 Agent 可用工具范围。

如果你想理解 Bear Code 为什么能拆分复杂任务，这一层很关键。

## 15. 第十三站：`agents/session.py`、`agents/ui.py`、`agents/frontmatter.py`

这些是支撑模块，建议最后看：

- `session.py`：会话保存与恢复，折叠记录落盘；
- `ui.py`：终端输出、工具调用、子 Agent 标识；
- `frontmatter.py`：Markdown frontmatter 解析与生成。

它们不决定项目主线，但决定项目是否真正可运行、可保存、可回放。

## 16. 一张总览图

```text
main.py
  -> Agent.chat()
    -> prompt.py
    -> memory.py
    -> skills.py
    -> mcp_client.py
    -> subagent.py
    -> tools.py
    -> online_skill_evolution.py
    -> skill_evolution.py
    -> online_skill_eval.py
    -> session.py
```

## 17. 读完以后应该能回答的问题

如果你真的读完这套源码，应该可以直接回答这些问题：

- 一次请求怎么跑完整个 Agent Loop？
- 模型调用工具前后发生了什么？
- 权限模式怎么影响工具执行？
- `compact_context` 为什么不是简单压缩，而是状态重组？
- Skills 怎么发现、怎么检索、怎么执行？
- 用户反馈怎么变成可复用 Skill？
- Skill 为什么要做 replay、规则评测和 champion？
- Memory 和 session memory 有什么区别？
- MCP 和子 Agent 为什么能被统一纳入 Runtime？

如果这些问题都能答清楚，你就已经真正理解 Bear Code 了。
